## KeyKeeper 保证的

- **值不会无意间落到 Agent 手里。** 它们在 macOS 钥匙串里，只经 `keykeeper run` 进入你批准的那条命令的环境变量。那条命令拿到的是真实的值；输出脱敏只替换原样出现的值，`--tty` 时关闭。Agent 新建的 key 只能注入：KeyKeeper 自己不打印、不返回。
- **按调用方批准，而不是按次。** 新的应用、终端或脚本第一次来要时，由你决定允许多久。KeyKeeper 从正在运行的进程里认出调用方：经 `keykeeper` 命令来的请求，认它是从哪个应用或文件启动的；直接连过来的程序，认它的代码签名，没签名就认路径；从不认它自报的名字。这能把你用的各个程序区分开，但挡不住已经在你账号下运行的恶意软件冒充其中某一个。授权存在一个只有 KeyKeeper 能写的钥匙串条目里。
- **记录了什么**：每个已批准的调用方最后一次用 key 的时间、没经批准的后台读取，以及需要批准或错过批准的请求。这不是完整的审计记录。授权随时可撤销。
- **没有遥测、分析或崩溃上报。** 会离开你 Mac 的只有：每 6 小时向 GitHub 检查一次更新，以及下载签名更新；可选的加密 iCloud 同步（默认关闭）；保存 key 时，如果模板定义了校验，向该服务商发一次只读验证请求；以及你自己配置的可选审查员模型。

## KeyKeeper 不保证的

<Callout type="warn" title="被你批准的程序可以滥用值">
`keykeeper run` 把值交给你批准的那条命令。那条命令能对它做任何事——`echo $KEY | base64`、写进文件、发到别处。输出脱敏只抓原文，抓不到编码过的。
这条边界和 1Password 的 `op run`、Doppler 的 `doppler run` 以及所有环境变量注入工具相同。KeyKeeper 的回答是让批准这件事有据可依：它给你看命令、调用方、以及调用方声明过什么。
</Callout>

- **没签名的程序按路径认**；换掉那个路径上的文件就继承了它的授权。窗口会说明这一点。
- **在你的 macOS 账号下运行的恶意程序**可以在你已批准的应用里跑命令、读取正在运行的命令的环境变量、冒充已批准的调用方、向你发起授权请求，也可以在 key 还在剪贴板上时读走它。KeyKeeper 自己写入剪贴板时标记为隐藏并会清除，但护不住你从网站复制到保存之前的那一段。
- KeyKeeper **不是密码管理器**：它只放给 Agent 用的开发凭据，刻意和你的个人密码分开。

## 审查员看不到值

可选的第二模型审查员收到的是 key 的名字、调用方写的理由和命令、声明用途、一行历史。它的 key 存在 KeyKeeper 自己的钥匙串条目里，
不是一条凭据，本机程序没法把它改指向别处。

## 报告问题

安全问题：security@keykeeper.dev，或在 GitHub 上私下报告。已公开的安全公告在仓库的 [Security 页](https://github.com/IvyYang1999/KeyKeeper/security/advisories)。2026-09-14 两轮安全审查的发现已在 0.3.4 修复，更新说明里有列。这两轮审查由没参与写代码的 AI Agent 完成，不是第三方审计。
