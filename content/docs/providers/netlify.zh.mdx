## Agent 做什么

```bash
keykeeper providers show netlify
keykeeper save --provider netlify --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c netlify -- <你的命令>
```

`--provider netlify` 会补上凭据 ID 和字段名。这些环境变量就是 Netlify 自家工具读的那个，不需要任何映射。

## 只有你能做的

<Steps>
<Step>Sign in to Netlify</Step>
<Step>Open Applications → Personal access tokens</Step>
<Step>Choose an expiration and SAML team access only if needed</Step>
<Step>复制 key，然后在 KeyKeeper 的窗口里确认保存。</Step>
</Steps>

## 该选什么

Personal tokens are account-wide. Set an expiration, do not opt into SAML team access unless the task needs that team, and prefer OAuth for a public integration.

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Netlify 的 key（没有形状规则）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** KeyKeeper 自己发送 `GET https://api.netlify.com/api/v1/user`，key 放在 `Authorization` 请求头里（reads the authenticated user）。Agent 收到的是「接受」「拒绝」或「联系不上」——从不是值。


## 轮换与过期

No universal expiry policy was confirmed for this credential type. Record the date shown by the provider, or leave it unknown. 在 [app.netlify.com](https://app.netlify.com/user/applications#personal-access-tokens) 轮换或撤销。
