## Agent 做什么

```bash
keykeeper providers show amux
keykeeper save --provider amux --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c amux -- <你的命令>
```

`--provider amux` 会补上凭据 ID 和字段名。这些环境变量就是 Amux API 自家工具读的那个，不需要任何映射。

## 只有你能做的

<Steps>
<Step>登录 Amux</Step>
<Step>先选择个人或组织 workspace 作为计费主体</Step>
<Step>充值后在 API keys 页面创建项目专用 key</Step>
<Step>确认该 workspace 的余额</Step>
<Step>复制 key，然后在 KeyKeeper 的窗口里确认保存。</Step>
</Steps>

## 该选什么

key 属于 workspace，费用由该 workspace 所属账户承担；按项目拆分 key。当前官方说明为预付按量计费，尚无订阅。

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Amux API 的 key（没有形状规则）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** Amux API 没有 KeyKeeper 可用的只读接口，第一次真实调用就是测试。


## 接入地址

这把 key 是下面这些地址的 bearer token。`keykeeper run` 只设置上面的环境变量，base URL 要你自己在客户端里指。

- **OpenAI compatible**——`https://gateway.amux.ai/v1`
- **Anthropic Messages**——`https://gateway.amux.ai`
- **Gemini native**——`https://gateway.amux.ai`

## 轮换与过期

官方未说明统一到期策略；完整 key 可在 keys 页面再次查看，不需要仅为找回值而轮换。 在 [amux.ai](https://amux.ai/keys) 轮换或撤销。
