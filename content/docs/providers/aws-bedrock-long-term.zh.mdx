## Agent 做什么

```bash
keykeeper providers show aws-bedrock-long-term
keykeeper save --provider aws-bedrock-long-term --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c aws-bedrock-long-term -- <你的命令>
```

`--provider aws-bedrock-long-term` 会补上凭据 ID 和字段名。这些环境变量就是 Amazon Bedrock 自家工具读的那个，不需要任何映射。

## 该选什么

长期 key 由 IAM service-specific credential 支撑；仅用于探索，并在 Advanced permissions 中保留实际需要的 Bedrock 权限。

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Amazon Bedrock · Long-term bearer key 的 key（没有形状规则）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** Amazon Bedrock · Long-term bearer key 没有 KeyKeeper 可用的只读接口，第一次真实调用就是测试。


## 接入地址

这把 key 是下面这些地址的 bearer token。`keykeeper run` 只设置上面的环境变量，base URL 要你自己在客户端里指。

- **Bedrock Converse**——`https://bedrock-runtime.{region}.amazonaws.com`（AWS Region）

## 轮换与过期

有效至创建时配置的到期日期；具体日期必须以 AWS 创建结果为准。 在 [console.aws.amazon.com](https://console.aws.amazon.com/bedrock) 轮换或撤销。
