## Agent 做什么

```bash
keykeeper providers show azure
keykeeper save --provider azure --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c azure -- <你的命令>
```

`--provider azure` 会补上凭据 ID 和字段名。这些环境变量就是 Azure Entra service principal · Client secret 自家工具读的那个，不需要任何映射。

## 只有你能做的

<Steps>
<Step>Sign in to Azure</Step>

<Step>Create a client secret with the shortest suitable expiry</Step>

<Step>复制 key，然后在 KeyKeeper 的窗口里确认保存。</Step>

## 该选什么

Prefer workload identity or managed identity. For a service principal, assign a task-specific role at resource or resource-group scope rather than subscription-wide Contributor.

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Azure Entra service principal · Client secret 的 key（没有形状规则）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** Azure Entra service principal · Client secret 没有 KeyKeeper 可用的只读接口，第一次真实调用就是测试。


## 轮换与过期

Client secrets expire on the date chosen at creation. 在 [portal.azure.com](https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade) 轮换或撤销。
