## What the agent does

```bash
keykeeper providers show google-cloud
keykeeper save --provider google-cloud --from-file /path/to/google-application-credentials.json --create --purpose "what this task does"
keykeeper run -c google-cloud -- <your command>
```

`--provider google-cloud` fills in the credential id and the field. The environment
variable is the one Google Cloud's own tools read, so nothing has to be mapped.

## What to choose

Prefer Application Default Credentials or workload identity. If a downloaded key is unavoidable, use a dedicated service account with resource-level, task-specific IAM roles — never Owner or Editor.

<Callout type="info">
The agent is told the same thing. It opens the page for you and says what to pick; it never
logs in, passes 2FA or pays on your behalf.
</Callout>

## What KeyKeeper checks

- **Before writing:** the value must look like a Google Cloud key (shown once when created). A wrong paste is refused before anything is stored, and the agent is told why — without the value.
- **After saving:** Google Cloud offers no read-only endpoint KeyKeeper can use, so the first real call is the test.


## Rotation and expiry

User-managed service-account keys usually remain valid until revoked, but organization policy can impose expiry. Record a date only when the console or policy shows one. Rotate or revoke at [console.cloud.google.com](https://console.cloud.google.com/iam-admin/serviceaccounts).
