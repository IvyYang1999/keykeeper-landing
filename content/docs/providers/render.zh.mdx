## Agent 做什么

```bash
keykeeper providers show render
keykeeper save --provider render --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c render -- <你的命令>
```

`--provider render` 会补上凭据 ID 和字段名。这些环境变量就是 Render 自家工具读的那个，不需要任何映射。

## 该选什么

Render API keys currently cover every workspace the user belongs to and have no scopes. Use a dedicated account or short-lived key for sensitive automation.

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Render 的 key（没有形状规则）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** KeyKeeper 自己发送 `GET https://api.render.com/v1/users`，key 放在 `Authorization` 请求头里（reads the user associated with the key）。Agent 收到的是「接受」「拒绝」或「联系不上」——从不是值。


## 轮换与过期

No universal expiry policy was confirmed for this credential type. Record the date shown by the provider, or leave it unknown. 在 [dashboard.render.com](https://dashboard.render.com/u/settings#api-keys) 轮换或撤销。
