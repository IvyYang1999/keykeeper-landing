## Agent 做什么

```bash
keykeeper providers show resend
keykeeper save --provider resend --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c resend -- <你的命令>
```

`--provider resend` 会补上凭据 ID 和字段名。这些环境变量就是 Resend 自家工具读的那个，不需要任何映射。

## 该选什么

权限选 Sending access，并限定到任务发信用的那一个域名。Full access 能管理域名和其他 key，不要建议。

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Resend 的 key（以 `re_` 开头）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** KeyKeeper 自己发送 `GET https://api.resend.com/domains`，key 放在 `Authorization` 请求头里（列出域名；仅发送的 key 会回「受限」，这同样证明它是真的）。回应里带 `restricted_api_key` 的受限 key 也算有效。Agent 收到的是「接受」「拒绝」或「联系不上」——从不是值。


## 轮换与过期

key 不过期；Resend 建议删掉 30 天没用的 key。 在 [resend.com](https://resend.com/api-keys) 轮换或撤销。
