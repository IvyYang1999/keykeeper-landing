## Agent 做什么

```bash
keykeeper providers show supabase
keykeeper save --provider supabase --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c supabase -- <你的命令>
```

`--provider supabase` 会补上凭据 ID 和字段名。这些环境变量就是 Supabase Management API 自家工具读的那个，不需要任何映射。

## 该选什么

这是 Supabase CLI 和 Management API 用的账号 access token，权限等于整个账号，所以要设过期。应用自己访问数据库请用项目的 Settings → API Keys：给客户端用 publishable（sb_publishable_），secret（sb_secret_）只放在服务端。

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 Supabase Management API 的 key（以 `sbp_` 开头）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** KeyKeeper 自己发送 `GET https://api.supabase.com/v1/projects`，key 放在 `Authorization` 请求头里（列出这个 token 能看到的项目）。Agent 收到的是「接受」「拒绝」或「联系不上」——从不是值。


## 轮换与过期

创建时设过期；项目 API key 永不过期。 在 [supabase.com](https://supabase.com/dashboard/account/tokens) 轮换或撤销。
