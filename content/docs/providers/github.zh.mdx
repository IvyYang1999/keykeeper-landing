## Agent 做什么

```bash
keykeeper providers show github
keykeeper save --provider github --from-clipboard --create --purpose "这个任务是做什么的"
keykeeper run -c github -- <你的命令>
```

`--provider github` 会补上凭据 ID 和字段名。这个字段的环境变量就是 GitHub 自家工具读的那个，不需要任何映射。

## 该选什么

Fine-grained token：Repository access 选 Only select repositories（任务涉及的仓库），权限只给任务需要的（比如 Contents: Read），其余保持 No access。过期：30 天以内。

<Callout type="info">
Agent 被告知的是同一件事。它替你打开页面、说明该选什么；它从不替你登录、过 2FA 或付费。
</Callout>

## KeyKeeper 检查什么

- **写入前：** 值必须像一把 GitHub 的 key（以 `github_pat_` 或 `ghp_` 开头，至少 40 个字符）。贴错了会在存入之前被拒绝，并告诉 Agent 原因——不含值。
- **保存后：** KeyKeeper 自己发送 `GET https://api.github.com/user`，key 放在 `Authorization` 请求头里（读取 token 所属的账号（不需要任何权限））。Agent 收到的是「接受」「拒绝」或「联系不上」——从不是值。

## 轮换与过期

Fine-grained token 在所选日期过期（1–366 天，或永不）；一年没用的 classic token 会被删除。 在 [github.com](https://github.com/settings/personal-access-tokens) 轮换或撤销。
